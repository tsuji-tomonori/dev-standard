# 多ラウンドの聞き取り

意味保存・推測の校正・日本語の距離は既存[semantic-articulation-protocol.md](../../calibrated-collaborative-listening/references/semantic-articulation-protocol.md)と[japanese-response-patterns.md](../../calibrated-collaborative-listening/references/japanese-response-patterns.md)を使う。ここでは新規開発の会話順序だけを補う。研究上の範囲・限界は[evidence-map.md](evidence-map.md)を参照する。

## 順序と負担

1. 初回の必須動作はSKILL本文に従う。例: 「何を楽にしたいですか。最近、勉強会の資料共有で困った場面を一つ教えてください」。solution候補を先に並べて回答をanchorしない。
2. 回答の語彙を使って利用者・中心task・データへ進み、必要な例外・重要制約を確認する。最初から専門用語の全項目を尋ねない。
3. 広い理解の後、結果を変える数値・選択・境界を閉じた質問で確かめる。選択肢は偏らせず自由な訂正を許す。
4. 大きな理解の変更や矛盾は短い言い換えでgroundingし、食い違った箇所をrepairする。毎発言の全復唱は不要。
5. 観点台帳とエンティティ走査の未処置類型を再判定し、次の重要な不足だけを聞く。確認前の締めの開いた質問を1回聞き、回答の不足を処置してサマリへ移る。

この新規開発contextでは、未処置の独立項目が複数残るとき、短く具体的に答えられる低負担の最大3問をまとめることを既定にする（ED-L02）。権限・保持等の価値判断も互いに独立し低負担ならまとめられる。依存する問い・価値衝突・矛盾修復だけ1問ずつ進める。長い回答・戸惑い・回答漏れが出たら負担を下げて1問へ戻す。番号ではなく独立した回答要求を数え、複数判断を一つのyesへ束ねない。既存傾聴Skill全般の1問既定を変更するものではない。

小規模な新規アプリでは、目的・例→重要類型の確認→締め質問→サマリの流れで概ね6〜8往復以内にサマリへ到達する目安を使う（ED-L05）。上限ではなく、超えそうなら残りの独立項目を一括化するか、回答済み方針の低リスクな実装細部をサマリの既定値へ移す判断の合図である。重要な未回答や矛盾は回数のために打ち切らない。最大3問も往復数もローカル方針（L）であり、研究が最適回数を示したとはしない。

適切な例: 「使う端末は何ですか」「同時に使うのは何人ですか」を、利用者が状況を説明済みで短く答えられる場合に分けた2問として示す。二重質問「簡単で速く安全にしたいですよね」は複数判断を一つのyesへ束ねるため避ける。question countは番号でなく独立した回答要求の数を数える。

## 質問の修正

| 失敗 | 修正と目的 |
|---|---|
| 誘導・前提入り | 「通知も必要ですよね」→「資料を掲載した後、今は誰が何をしていますか」。必要性を回答から判断 |
| 黙従を招く確認 | 「当然、管理者だけですよね」→「変更できる人の範囲はどうしますか」。短いyesを理解の証拠にしない |
| 未回答値を一つ埋め込む確認 | 「資料はPDFでしょうか」「PDFでよいですか」→「資料はどの形式で扱いますか」。選択肢を出すなら「PDF、画像、テキスト、それ以外」のように偏らせない。自分の既定値は質問ではなく確認サマリの台帳へ出す |
| アンカリング・順序効果 | 先に高度な機能一覧を出さない。目的と実例→候補→境界へ。影響をゼロとは主張しない |
| 二重質問 | 保持と削除権限を一つのyes/noに結合しない。独立ID/問いへ分ける |
| 尋問 | 同じ項目の再質問、全schemaの回答要求、長い専門語一覧を避ける。聞く理由は必要なら短く伝える |
| 実装細部の個別確認・一問ずつの過補正 | 方針回答後の低リスクな範囲検証・起動時点・表示・付帯機能は値・根拠・誤った場合の影響をサマリへ出す。残る独立低負担項目は最大3問をまとめる |
| solution固定 | 「AIを付けたい」→「それで、どの作業ができれば役立ちますか」。不要ならscope外候補として確認 |
| 反発・自律性の喪失 | 「これを決めるべき」ではなく選択の結果を説明し、訂正と保留の権利を残す |

Pewのsurvey研究を対話へそのまま一般化せず、質問の歪みを避ける設計上の注意として使う。Banoらの要求面接研究はnovice面接の失敗の識別に使い、AI対話での効果量を主張しない。傾聴は迎合・診断を意味しない。

質問の型は情報の出方を変えるため、目的・操作・条件に応じて問いを組み立てる（[ED-R09](evidence-map.md): Browne & Rogichの3手法比較）。語彙の強さや未確認の前提を避ける注意はED-R12（Loftus & Palmer）の映像記憶実験にも基づく。どちらも日本語LLM対話の最適順序・質問数を実証していない。技法の系統的レビューの所在と今回の確認限界はED-R11を参照する。

## 実例と意味の修復

Critical incidentの発想を借り、直近の成功/失敗一例から「起点・誰の操作・入力・起きた結果・困った影響」を引き出す。記憶は完全な記録ではなく、報告された一例を頻度や全利用者へ一般化しない。正式な認知面接を行ったと称したり、想像で欠けた記憶を補わせたりしない。

曖昧性を次の形で検出し、差が成果を変えるときだけ聞く（分類と運用はL）。

曖昧な発言は、欠けたdomain知識を見つける機会にもなる（[ED-R10](evidence-map.md): Ferrariらの34面接）。一義に決めつけず具体的な解釈差を確認する。以下の4分類は同研究の4分類を複製したものではない。

- 語彙: 「すぐ」「大量」「終了」→操作・件数・時間・状態の具体基準。
- 構造: 「講師と運営担当者の資料を削除」→誰が誰のどの資料を削除できるか。
- 指示: 「それも残す」→何のデータ・履歴を指すか。
- スコープ: 「全員」「いつも」「以外」→対象役割・期間・例外の範囲。

Griceの協調原理は、発言の目的に照らして不足や含意を考える分析の助けとする。「便利にしたい」から通知・認証・公開を承認済みと推定しない。暗黙の含意は候補に留める。

矛盾例: 最初「勉強会の参加者はみんな資料を編集できる」、後で「聴講者は変えないで」。修復: 「資料を変更できるのは発表者までで、聴講者は見るだけ、という理解で合っていますか」。旧発言のどの範囲が変わったかを明示し、誤りを人格評価にしない。

自然な数値化例: 「『すぐ』の目安を決めたいです。普段の資料数で、検索に何秒くらいなら困りませんか」。未回答の上限を先に押し付けない。利用者が基準を持たず低リスクな既定値にできる場合は、測定可能な値と根拠・誤った場合の影響を確認サマリへ示す。

## 確認前の否定的シナリオ

締めには「起きると困ること・やってはいけないことは何ですか」と開いて1回聞く。候補の失敗一覧や既定値を先に示さず、利用者の言葉で条件と影響を得る。具体的な出来事と影響を聞く発想はED-R06、質問の型と観点coverageを組み合わせる背景はED-R09による。このタイミング・1回という回数・否定的な問いの採用はED-L04のローカル方針であり、これらの研究が本手順の漏れ削減やLLMでの改善を実証したとはしない。
